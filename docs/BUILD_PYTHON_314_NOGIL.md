# Build Python 3.14.3 with No-GIL from Source

The standard macOS installer may not include no-GIL support. To get Python 3.14.3 with GIL disabled by default, you need to build from source with the `--disable-gil` flag.

## Prerequisites

1. **Install Xcode Command Line Tools**:
   ```bash
   xcode-select --install
   ```

2. **Install Homebrew dependencies**:
   ```bash
   brew install openssl readline sqlite3 xz zlib tcl-tk
   ```

## Build Steps

### Step 1: Download Source Code

```bash
cd ~/Downloads
curl -O https://www.python.org/ftp/python/3.14.3/Python-3.14.3.tgz
tar -xzf Python-3.14.3.tgz
cd Python-3.14.3
```

### Step 2: Configure with No-GIL

```bash
./configure \
  --prefix=$HOME/.local/python3.14-nogil \
  --enable-optimizations \
  --with-lto \
  --disable-gil \
  CPPFLAGS="-I$(brew --prefix openssl)/include -I$(brew --prefix readline)/include" \
  LDFLAGS="-L$(brew --prefix openssl)/lib -L$(brew --prefix readline)/lib"
```

**Key flags explained**:

- **`--disable-gil`**: 
  - **What it does**: Disables the Global Interpreter Lock (GIL) in Python, enabling true multi-threading
  - **Why it matters**: The GIL prevents multiple Python threads from executing Python bytecode simultaneously. With `--disable-gil`, Python can run multiple threads in parallel, potentially improving performance for CPU-bound multi-threaded applications
  - **Trade-offs**: Some C extensions may not be compatible with no-GIL mode. Python 3.14 includes compatibility shims, but you should test your dependencies
  - **Result**: After building, `sys._is_gil_enabled()` will return `False` by default (no need for `-X nogil` flag)

- **`--prefix=$HOME/.local/python3.14-nogil`**: 
  - **What it does**: Sets the installation directory where Python will be installed
  - **Why use this path**: Installing to `$HOME/.local/` means:
    - No `sudo` required (user-level installation)
    - Doesn't interfere with system Python or other Python installations
    - Easy to remove (just delete the directory)
    - Follows Linux/macOS convention for user-installed software
  - **Alternative**: You could use `/usr/local/python3.14-nogil` but would need `sudo` for installation
  - **Result**: Python binaries, libraries, and modules will be installed under this directory

- **`--enable-optimizations`**: 
  - **What it does**: Enables Profile-Guided Optimization (PGO) during the build process
  - **How it works**: 
    1. Python is built normally
    2. Python runs a set of benchmark scripts to profile common operations
    3. Python is rebuilt using this profile data to optimize hot code paths
  - **Benefits**: 
    - 10-20% performance improvement for typical Python workloads
    - Better instruction cache usage
    - More efficient branch predictions
  - **Trade-off**: Build time increases significantly (can take 2-3x longer)
  - **Result**: Faster Python interpreter at runtime

- **`--with-lto`**: 
  - **What it does**: Enables Link-Time Optimization (LTO) during compilation
  - **How it works**: 
    - Compiler optimizes across object file boundaries at link time
    - Can inline functions from other compilation units
    - Removes unused code more effectively
    - Better inter-procedural optimizations
  - **Benefits**: 
    - Additional 5-10% performance improvement
    - Smaller binary size (dead code elimination)
    - Better optimization when combined with `--enable-optimizations`
  - **Requirements**: Requires a compiler with LTO support (Clang on macOS has this)
  - **Trade-off**: Slightly longer build time and more memory during compilation
  - **Result**: More optimized Python binary

**Additional flags in the configure command**:

- **`CPPFLAGS="-I$(brew --prefix openssl)/include -I$(brew --prefix readline)/include"`**: 
  - Tells the compiler where to find header files for OpenSSL and Readline libraries
  - Required because Homebrew installs these in non-standard locations
  - `-I` flag adds include directories to the compiler's search path

- **`LDFLAGS="-L$(brew --prefix openssl)/lib -L$(brew --prefix readline)/lib"`**: 
  - Tells the linker where to find library files (.dylib files on macOS)
  - Required to link against Homebrew-installed libraries
  - `-L` flag adds library directories to the linker's search path

### Step 3: Build

```bash
# Build using all CPU cores (this will take 10-30 minutes)
make -j$(sysctl -n hw.ncpu)
```

**What this command does**:

- **`make`**: The build system that compiles Python from source code
  - Reads the `Makefile` generated by `configure`
  - Compiles all C source files into object files
  - Links object files into the final Python executable and libraries
  - Handles dependencies between files automatically

- **`-j` flag**: Enables parallel compilation
  - Without `-j`: Compiles files one at a time (sequential, slow)
  - With `-j N`: Compiles up to N files simultaneously (parallel, much faster)
  - Example: `-j 8` means compile up to 8 files at the same time

- **`$(sysctl -n hw.ncpu)`**: Dynamically detects your CPU core count
  - **`sysctl -n hw.ncpu`**: macOS command that returns the number of CPU cores
    - Example: On an 8-core Mac, this returns `8`
    - Example: On a 4-core Mac, this returns `4`
  - **`$()`**: Command substitution - runs the command and uses its output
  - **Result**: The `-j` flag gets the number of your CPU cores automatically

**Example**:
- If you have an 8-core Mac: `make -j$(sysctl -n hw.ncpu)` becomes `make -j8`
- This compiles up to 8 files simultaneously, using all 8 CPU cores

**Why use all cores?**:
- **Speed**: Parallel compilation is much faster than sequential
  - Sequential build: ~45-60 minutes
  - Parallel build (8 cores): ~10-15 minutes
- **Efficiency**: Utilizes all available CPU resources
- **Automatic**: Adapts to your machine (works on 4-core, 8-core, 16-core, etc.)

**Build process overview**:
1. Compiles hundreds of C source files (`.c` files) into object files (`.o` files)
2. Links object files into Python executable (`python3.14`)
3. Builds Python standard library modules
4. Runs tests (if `--enable-optimizations` is used, runs profiling benchmarks)
5. Creates final installation files

**What you'll see**:
- Lots of compilation output scrolling by
- Multiple compiler processes running simultaneously
- CPU usage at 100% (all cores working)
- Progress messages for each file being compiled
- Final message: "Python build finished successfully!"

**Time estimate**:
- **Without optimizations**: 10-15 minutes (8-core Mac)
- **With `--enable-optimizations`**: 20-30 minutes (runs profiling twice)
- **With `--enable-optimizations` and `--with-lto`**: 25-35 minutes

**If build fails**:
- Check error messages in the output
- Common issues: missing dependencies, insufficient memory, disk space
- You can retry with fewer cores: `make -j4` (uses 4 cores instead of all)

### Step 4: Install

```bash
make altinstall
```

**What this command does**:

- **`make altinstall`**: Installs Python without overwriting existing Python installations
  - Copies the compiled Python executable and libraries to the installation directory
  - Installs Python as `python3.14` (not `python3` or `python`)
  - Preserves any existing `python3` or `python` commands on your system

**Why use `altinstall` instead of `install`?**:

- **`make install`** (NOT recommended):
  - Installs as `python3` and `python` (overwrites system defaults)
  - Can break system Python or other Python installations
  - May interfere with macOS system tools that depend on Python
  - Requires `sudo` for system directories

- **`make altinstall`** (Recommended):
  - Installs as `python3.14` (version-specific name)
  - Doesn't overwrite existing Python installations
  - Safe - won't break system Python or other versions
  - No `sudo` needed when installing to `$HOME/.local/`
  - Allows multiple Python versions to coexist

**What gets installed**:

1. **Python executable**: `$HOME/.local/python3.14-nogil/bin/python3.14`
2. **Python libraries**: `$HOME/.local/python3.14-nogil/lib/python3.14/`
3. **Header files**: `$HOME/.local/python3.14-nogil/include/python3.14/`
4. **Documentation**: `$HOME/.local/python3.14-nogil/share/`
5. **Man pages**: `$HOME/.local/python3.14-nogil/share/man/`
6. **pip and other tools**: `$HOME/.local/python3.14-nogil/bin/pip3.14`, etc.

**Installation process**:
- Copies all compiled files from the build directory to the installation directory
- Sets up Python's standard library
- Creates symbolic links for `python3.14`, `pip3.14`, etc.
- Takes 1-2 minutes (much faster than the build step)

**After installation**:
- Python is ready to use at: `$HOME/.local/python3.14-nogil/bin/python3.14`
- You can add it to PATH to use `python3.14` command directly
- Your system Python remains untouched and functional

**Example**:
```bash
# After altinstall, you can use:
$HOME/.local/python3.14-nogil/bin/python3.14 --version
# Python 3.14.3

# Or after adding to PATH:
python3.14 --version
# Python 3.14.3

# System Python still works:
python3 --version
# Python 3.9.6 (or whatever was there before)
```

This installs to `$HOME/.local/python3.14-nogil/bin/python3.14`

### Step 5: Add to PATH

```bash
# Add to your ~/.zshrc
echo 'export PATH="$HOME/.local/python3.14-nogil/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

### Step 6: Verify No-GIL is Enabled

```bash
# Check version
python3.14 --version

# Verify GIL is disabled (should print: GIL disabled: True)
python3.14 -c "import sys; print('GIL disabled:', not sys._is_gil_enabled())"
```
